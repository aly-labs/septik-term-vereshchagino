# Размещение сайта на GitHub (GitHub Pages)

Сайт готов к GitHub Pages: все пути относительные, поэтому он работает
и по адресу `https://ваш-логин.github.io/`, и по адресу
`https://ваш-логин.github.io/название-репозитория/`.

> Важно: GitHub Pages — это **статический хостинг**. Сайт и каталог работают,
> а вот **отправка заявок на нём работать не будет** (нет сервера `server.py`).
> Формы покажут сообщение «Не удалось отправить заявку. Позвоните нам…».
> Чтобы заявки работали на GitHub Pages, нужен внешний сервис форм
> (Formspree, Web3Forms, Cloudflare Worker и т. п.) — см. раздел «Заявки на GitHub Pages».

---

## Вариант 1. GitHub Desktop (рекомендую новичкам)

1. Зарегистрируйтесь на https://github.com (если ещё нет аккаунта).
2. Скачайте и установите **GitHub Desktop**: https://desktop.github.com
3. В GitHub Desktop: **File → Add local repository…** → выберите папку
   `C:\Users\alyvl\OneDrive\Документы\Проект по умолчанию`.
4. Окно «Publish repository»: придумайте название репозитория, например
   `septik-term-vereshchagino`. Рекомендую снять галку «Keep this code private»,
   либо оставить приватным, если не хотите, чтобы проект видели.
   Нажмите **Publish repository**.
5. Во вкладке **Changes** нажмите **Commit to main** (первый коммит),
   затем **Push origin** (кнопка появится сама) — на тот момент он уже будет на GitHub.

> Совет: чтобы сайт был по «короткому» адресу `https://ваш-логин.github.io/`
> (без папки), назовите репозиторий ровно `ваш-логин.github.io`
> (например, `ivanov.github.io`).

## Вариант 2. Только браузер, без установки программ

1. На github.com нажмите **+ → New repository**, дайте имя (например,
   `septik-term-vereshchagino`), не создавайте README, нажмите **Create repository**.
2. На открывшейся странице нажмите **uploading an existing file**.
3. Перетащите в окно **все файлы и папки** из проекта: `index.html`,
   `privacy.html`, `robots.txt`, `sitemap.xml`, папки `css`, `js`, `data`, `img`.
   ВАЖНО: перетаскивайте содержимое папки проекта (сами файлы), а не саму папку.
4. Нажмите **Commit changes**.

## Включение GitHub Pages (обязательный шаг для обоих вариантов)

1. Откройте репозиторий → **Settings**.
2. Слева выберите **Pages**.
3. В блоке **Build and deployment**: **Source → Deploy from a branch**,
   **Branch → main / (root)** → **Save**.
4. Подождите 1–3 минуты. Сверху появится зелёная плашка
   «Your site is live at …». Это и есть адрес сайта:
   `https://ваш-логин.github.io/септик-репозиторий/`.

После каждого изменения файлов: закоммитьте и запушьте — GitHub Pages
обновит сайт автоматически через пару минут.

## Советы после публикации

- Замените `https://example.ru/` на реальный адрес в файлах:
  `index.html` (тег `<link rel="canonical">`), `robots.txt`, `sitemap.xml`.
- Подключите Яндекс.Метрику, когда будет готово.
- Почистите тестовые данные: удалите `leads.jsonl`, `gh-test/`, `__pycache__/`
  (их на GitHub загружать не нужно).

## Заявки на GitHub Pages (чтобы формы реально отправлялись)

GitHub Pages не умеет принимать заявки. Три рабочих способа:

1. **Formspree / Web3Forms.** Зарегистрируйтесь, получите адрес формы и укажите
   его в `js/config.js` как `leadEndpoint: "https://formspree.io/f/ваш-id"`.
   Заявки будут приходить на почту. Это проще всего.
2. **Cloudflare Workers.** Бесплатная функция-прокси (аналог нашего `/api/lead`),
   которая принимает заявку и пересылает в Telegram или n8n.
3. **n8n на бесплатном сервере** + любой вебхук с разрешённым CORS.

Пока интеграции нет, формы честно сообщают клиенту: «Позвоните нам по телефону».

## Вариант 3. Установить Git — тогда всё сделаю я

Если установите Git для Windows (https://git-scm.com) и GitHub CLI (https://cli.github.com)
и авторизуетесь в них, я смогу сам создать репозиторий, закоммитить файлы,
включить GitHub Pages и дать ссылку на готовый сайт — по вашим командам.
